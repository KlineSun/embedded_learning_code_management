# 多线程编程

## 一、为什么要使用多线程？

在程序中，如果有多项任务需要同时进行，一般建议将同时进行的两个任务放在不同的线程中进行；

如果几个任务之间存在相互关联，则还需要处理多进程之间的并发干扰；



知识点：

并发任务也可以使用多进程完成，然而进程间的通信(socket、信号量、管道、共享内存、队列)和并发处理(互斥锁不生效)更加难以处理，效率低，且创建进程和线程的损耗存在差异，具体差异如下：

### **1. 创建与销毁的损耗对比**

| **维度**     | **进程 (Process)**                 | **线程 (Thread)**                      | **损耗差异原因**                       |
| :----------- | :--------------------------------- | :------------------------------------- | :------------------------------------- |
| **内存占用** | 高（独立地址空间，复制父进程资源） | 低（共享进程地址空间，仅需栈和寄存器） | 进程需分配独立内存，线程共享进程资源。 |
| **CPU 开销** | 高（需初始化页表、文件描述符表等） | 低（仅需设置线程上下文）               | 进程需重建完整的执行环境。             |
| **创建时间** | 慢（微秒级）                       | 快（纳秒级）                           | 线程无需内核介入（用户态线程更快）。   |
| **销毁开销** | 高（需回收所有资源）               | 低（仅释放线程私有资源）               | 进程需清理独立的内存和内核结构。       |

**结论**：线程的创建和销毁开销通常比进程 **低 10-100 倍**（具体数值依赖系统和实现）。



### 2. **具体差异详解**

#### 1) 资源分配

- 进程
  - 拥有独立的虚拟地址空间、文件描述符表、信号处理表等；
  - 通过fork函数创建时，会默认复制父进程的所有资源(写时复制优化可减少实际内存拷贝)；
- 线程
  - 共享进程的地址空间、文件描述符、全局变量等；
  - 仅独立拥有栈、寄存器状态、和线程局部存储(TLS)。

#### 2）上下文切换

- 进程切换
  - 需切换页表(TLB刷新)、内核栈、寄存器等，开销大（约 1-10 μs）；
- 线程切换：
  - 若同属一个进程，切换时只需要切换寄存器、栈指针，开销小（约 100 ns-1 μs）；

#### 3）通信与同步

| **方式**     | **进程**                       | **线程**                   |
| :----------- | :----------------------------- | :------------------------- |
| **共享数据** | 需通过 IPC（管道、共享内存等） | 直接读写全局变量（需同步） |
| **同步机制** | 信号量、消息队列、文件锁       | 互斥锁、条件变量、原子操作 |
| **延迟**     | 高（内核介入）                 | 低（用户态操作）           |

#### 4）容错性

- **进程**：一个进程崩溃不会影响其他进程（隔离性强）。
- **线程**：一个线程崩溃可能导致整个进程退出（共享地址空间）。

#### 5）扩展性

- **进程**：分布式系统中可跨机器扩展（如微服务）。
- **线程**：单机多核并行优化（如计算密集型任务）。



### 3.**如何选择？**

| **场景**                     | **推荐选择** | **理由**                                  |
| :--------------------------- | :----------- | :---------------------------------------- |
| 需要高隔离性（如浏览器标签） | 进程         | 避免单个标签崩溃影响整体。                |
| 低延迟通信（如游戏服务器）   | 线程         | 共享内存通信快，适合实时性要求高的任务。  |
| 多机分布式计算               | 进程         | 天然支持跨机器部署（如 Kubernetes Pod）。 |
| 单机高性能计算（如矩阵运算） | 线程         | 减少上下文切换开销，充分利用多核 CPU。    |





#### 内核资源：

- 进程控制块：内核数据结构，存储进程元信息（PID、状态、优先级等）；对应内核中的task_struct；
- 虚拟地址空间：进程独占的线性地址范围，通过页表映射到物理内存；32 位系统默认 4GB（用户态 3GB，内核态 1GB）。
- 文件描述符列表：记录进程打开的文件、套接字等IO资源；如fd(0)表示标准输入、fd(1)表示标准输出；
- 信号处理列表：定义进程对信号的响应方式；如SIGINT的处理函数；
- 进程凭证：用户/组/ID （UID/GID）、权限标识；
- 定时器：进程相关的计时器，如alarm设置的超时；
- IPC资源：进程间通信资源（消息队列、信号量、共享内存等）；如：shmget()创建的共享内存段；



#### 用户态资源：

- 代码段：只读的可执行指令(如程序的二进制代码)

- 数据段：全局变量和静态变量（已初始化放在.data段，未初始化的放在.bss段）；

  - .data段：该段的数据在编译时已经确认了初始化的值，直接占用二进制文件的空间，程序运行时直接从二进制文件中加载到内存，不需要对变量的内存先进行清零操作；
  - .bss段：该段的数据在编译时无法确认初始化值，在编译时仅记录.bss段的大小，不存储实际数据，因此不占用二进制文件的大小；在程序加载时，操作系统会为.bss段分配内存，并全部自动填充为0（类似memset机制）；

  **注意：**

  - 定义在函数中的局部静态变量，即使函数未被调用，该变量依旧会存放在.data段：

  ```c
  void func() {
      static int local_static = 10;  // 实际存储在 .data 段（即使函数未调用）
  }
  ```

  - 显式地初始化为0，变量依旧会存放在.bss段，这是因为编译器优化导致的

- 堆：动态分配的内存，通过malloc和free管理；

- 栈：函数调用栈（局部变量、返回地址等），由编译器自动管理；

- 共享库：动态链接库，如.so文件，需要映射到进程地址空间；

- 线程资源：若进程拥有多个线程，每个线程有独立的栈和寄存器，共享其他资源；

## 二、多线程同步机制

### 1、全局变量

线程之间可以共享全局变量，通过全局变量能够传递信息，进行同步；



### 2、信号量

```c
#include<semaphore.h>

// 初始化信号量，线程间使用。其中value为初始值，需要赋值为0
int sem_init(sem_t *sem, int pshared, unsigned int value);

// 创建/打开信号量，进程间使用，用法类似open函数，如果创建信号量需要制定mode，表示信号量的权限，比如777
sem_t *sem_open(const char *name, int oflag, mode_t mode, unsigned int value);

// 阻塞等待信号量，直到信号量的值大于0
int sem_wait(sem_t *sem);

// 释放信号量，将信号量的值置为大于0，阻塞等待信号量的进程/线程将被唤醒
int sem_post(sem_t *sem);

// 销毁无名信号量
int sem_destroy(sem_t *sem);

// 关闭有名信号量
int sem_close(sem_t *sem);

// 删除有名信号量，立刻关闭所有进程/线程中打开的同名信号量
int sem_unlink(const char *name);
```



### 3、互斥锁

```c
#include <pthread.h>

// 初始化互斥锁，可以设置参数
int pthread_mutex_init(pthread_mutex_t *mutex, const pthread_mutexattr_t *attr);

int pthread_mutex_lock(pthread_mutex_t *mutex);

int pthread_mutex_unlock(pthread_mutex_t *mutex);

```



设置递归锁示例：

```c
// 设置递归锁属性
pthread_mutexattr_t attr;
pthread_mutexattr_init(&attr);
pthread_mutexattr_settype(&attr, PTHREAD_MUTEX_RECURSIVE);
pthread_mutex_init(&mutex, &attr);
pthread_mutexattr_destroy(&attr);
```



### 4、条件变量

```c
#include <pthread.h>

// 等待条件变量cond，与mutex配合使用，在临界区等待条件变量
// 开始等待前会先释放mutex，等被唤醒后会再尝试获取锁，获取锁成功之后才会返回0
int pthread_cond_wait(pthread_cond_t *cond, pthread_mutex_t *mutex);

// 释放条件变量
int pthread_cond_signal(pthread_cond_t *cond);

// 释放条件变量
int pthread_cond_broadcast(pthread_cond_t *cond);

```
