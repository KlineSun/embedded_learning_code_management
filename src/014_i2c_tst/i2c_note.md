# I2C介绍

## 一、I2C简介

​	I2C(integer integrated circle)，是一种同步，半双工，串行的通信方式，有飞利浦于1982年推出，常用于短距离，低俗，板极设备间（板上的各种芯片之间）通信；



## 二、基本特性

| 特性         | 说明                                                         |
| :----------- | :----------------------------------------------------------- |
| **通信方式** | 同步（带时钟信号）、串行（逐位传输）                         |
| **数据传输** | 半双工（同一时间只能发送或接收）                             |
| **总线结构** | 两线制：**SDA（数据线） + SCL（时钟线）**                    |
| **通信速率** | 标准模式（100 kbps）、快速模式（400 kbps）、高速模式（3.4 Mbps）等 |
| **寻址方式** | 7位或10位设备地址（支持多个设备共享总线）                    |
| **主从架构** | 1个主设备（Master）控制通信，多个从设备（Slave）响应         |
| **电平标准** | 通常3.3V或5V（需上拉电阻）                                   |

## 四、通信流程

**时序：**

- 起始信号：SCL高电平时，SDA由高电平转为低电平；
- 写地址信号：主机收到起始信号之后，会写入7位地址码 + 一位读写标志位(1=读，0=写)；
- 响应信号：从设备收到信号之后将SDA拉低表示收到；
- 数据交换：主从设备构建连接之后，开始通过总线进行数据传输，每次8位+ACK（ACK信号为低电平，需要响应设备输出1，拉低SDA）；
- 停止信号：SCL高电平时，SDA由低电平转为高电平；

## 五、总结

### 5.1 优缺点

**优点：**

- 仅需两根线，节省硬件资源；
- 支持多主多从，需要仲裁机制；
- 广泛引用于传感器、EEPROM、RTC等低速设备；



**缺点：**

- 半双工，同一时间只能有一个方向，传输效率低；
- 总线长度受限，一般1m以内；
- 需上拉电阻，影响信号完整性；



### 5.2 典型应用

- 传感器，如温度、湿度、加速度等；
- 存储器，如EEPROM；
- RTC实时时钟；
- LCD/OLED显示驱动；



### 5.3 总结

I²C是一种简单、低成本、广泛使用的短距离通信协议，适用于**嵌入式系统、单片机（如STM32、Arduino）与外设的通信**。掌握其基本时序和硬件连接是嵌入式开发的基础技能。



## 六、补充知识

### 6.1 多主多从机制

在i2c总线中，支持多个主设备多个从设备同时共享总线；需要通过仲裁机制和同步机制完成数据的传输；



#### 6.6.1 多主冲突和仲裁机制

当有多个主设备同时发起通信请求时，按照以下规则解决冲突：

##### 1、时钟同步

- 问题：不同主机需要的时钟频率可能不同；
- 解决方法：SCL采用线与的逻辑，任一主设备拉低SCL，总线即为低电平；
  - 主设备在SCL低电平时，检测是否被其他主设备拉低；
  - 慢速设备会延长时钟低电平，强制其他高速设备等待，也就是同步时钟；

##### 2、数据仲裁

规则：主设备在SDA上发送数据时，同时监听SDA的实际电平；

- 如果主设备发送1（释放SDA），同时检测到SDA为低电平，则该主线仲裁失败，退出总线；
- 仲裁失败的设备转为从设备模式，等待总线空闲后重试；

关键点：

- 仲裁基于数据内容，先发送0的获胜，因为线与逻辑，任意设备拉低，总线即为低电平，因此0优于1
- 仲裁过程不会破坏正在进行的数据传输(失败的主设备停止驱动主线，而获胜设备继续数据传输)；

##### 3、仲裁示例

假设两个主设备(MasterA和MasterB)同时发送起始条件和地址：

- Master A发送地址 `0x50`（二进制 `1010000`），Master B发送 `0x72`（二进制 `1110010`）。

- 在比较第2位时（Master A发`0`，Master B发`1`），Master A检测到SDA被自己拉低，而Master B检测到SDA实际为低（与自己发送的`1`冲突），**Master B仲裁失败**，停止驱动总线。

- Master A继续完成后续数据传输。



#### 6.6.2 多从设备寻址

- 每个设备都有唯一的地址(7位或者10位)，主设备通过地址来选择通信目标；
- 如果多个从设备地址相同，需要依靠片选(即CS)，或者软件协议来区分，但是i2c协议不推荐地址冲突；



#### 6.6.3 多主模式的限制与注意事项

- **时钟拉伸（Clock Stretching）**：
  - 从设备可能拉低SCL以延迟传输（如处理数据），主设备需支持此功能。

- **总线容量**：
  - 上拉电阻和总线电容影响最大速度（通常不超过400 kHz）。

- **错误恢复**：
  - 仲裁失败的主设备需重置I²C状态机，避免死锁。

- **软件支持**：
  - MCU的I²C硬件需支持多主模式（如STM32的I2C外设具有仲裁丢失标志`ARLO`）。



#### 6.6.4 多主多从总结

| **机制**       | **作用**                                                     |
| :------------- | :----------------------------------------------------------- |
| **时钟同步**   | 强制所有主设备使用最慢的SCL时钟，避免时序混乱。              |
| **数据仲裁**   | 通过SDA的“线与”逻辑，优先发送`0`的主设备获胜，其他主设备退出。 |
| **地址唯一性** | 从设备地址必须唯一，否则需硬件片选辅助。                     |
| **错误恢复**   | 仲裁失败的主设备需重置I²C模块，等待总线空闲后重试。          |





#### 6.6.5 上拉电阻和下拉电阻

![pull_down_resistor_new](E:\embedded_learning\embedded_learning_code_management\src\014_i2c_tst\pull_down_resistor_new.png)



- 上拉电阻：连接信号线到电源，确保输出引脚**默认为高电平**；在控制信号拉高（PNP结为拉高，NPN型为拉低），就连通了C极和E极，从而输出pin脚读到的就是**低电平**；
  	**输入信号`0`是否等于直接接地？**
  - **不完全等同**，但效果类似：
    - **直接接地**：Signal通过0Ω电阻接地，电压严格=0V（无限流，可能烧毁电路）。
    - **开漏拉低**：Signal通过MOSFET接地，MOSFET导通电阻极小（如0.1Ω），电压≈0V，但**受Rp限流保护**。
- 下拉电阻：引脚经过电阻接到GND，确保引脚**默认为低电平**，当控制信号拉高（PNP结为拉高，NPN型为拉低），就连通了C极和E极，从而输出pin脚读到的就是**高电平**；
